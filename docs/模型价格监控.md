# 独立模型价格监控

## 使用方法

1. 打开“模型价格”，所有 New API 和 Sub2API 渠道按行展示价格状态、监控范围及最近检测时间；点击渠道行展开，可同时展开多个渠道。
2. 展开后默认只查看已监控分组与模型，使用分组按钮切换，价格以紧凑表格展示。点击“管理模型”进入配置，再点击“自动检测分组”读取可选分组。
3. 勾选模型并保存后自动返回监控列表。可以搜索模型、按页查看，或者选择当前筛选结果。编辑时收起渠道会保留未保存的勾选，不会自动提交；保存前分组切换被锁定。
4. 渠道启用时，后台随渠道检测周期检查已选模型。点击“刷新价格”可以立即检测当前渠道，不检测其他渠道。
5. 普通浏览及折叠摘要只读取本地保存的监控结果，不自动向上游读取模型目录；目录仅在展开的“管理模型”中按需加载。
6. 价格变化显示新旧值、涨跌及币种，告警中心保存变化事件，通过已配置的通知设备和邮箱提醒。

## 与倍率监控的关系

- 两者配置、基准及实时刷新事件独立，可同时启用。取消其中一个，不改变另一个。
- “倍率”页面保留原有只读价格展示，提供独立价格监控入口。
- 模型价格是指定分组下的实际价格，包含适配器解析的适用倍率。倍率变化引起实际价格变化时，已启用的两种监控各自记录对应事件。
- 输入、输出和缓存价格归并展示；按次、图片及阶梯档位分别保留原有计价单位。不同币种之间不比较涨跌大小。

## 基准与异常处理

- 新选择只建立初始价格基准，不产生变化通知。重复保存已有选择不重置原基准。
- 数值先做十进制规范化，`1.00` 与 `1` 不视为变化，接口金额仍使用字符串。
- 模型暂时缺失、未公开固定价格或接口失败时，保留上次有效价格并显示异常，不误认为免费或价格归零。
- 实际变化事件与新基准在一个事务内保存，相同值不重复通知，发送失败使用原有通知重试流程。
- 手动更换渠道登录身份后保留选择并重新建立价格基准；更换渠道地址或类型时清理旧站点价格选择。自动续期不会清空基准。
- 暂停渠道会暂停定时价格检测；单独取消某分组模型监控不要求成功连接上游。

## 运维与数据

- 新增 `model_price_monitors` 表，保存已选择模型的当前及上次价格；不保存上游原始响应或登录秘密。
- 每渠道最多选择 20 个分组、500 个模型，复用现有请求超时、响应大小、SSRF 校验及渠道互斥锁。
- 价格变化事件类型为 `price_changed`，实时更新使用 `price.updated`。告警历史随系统历史保留设置清理。
- 新接口位于 `/api/targets/{id}/model-prices`，读取配置和保存选择使用 GET/PUT；`/groups` 使用 POST 发现分组；`/catalog?groupKey=...` 使用 GET 读取目录；`/check` 使用 POST 手动检测。
- 所有接口复用管理员会话和来源校验，基准由服务端重新读取上游后建立，不接受客户端提交价格。
- 部署前备份数据卷。新版本启动自动建表，重启保留配置、价格基准和待发送事件。回退旧镜像会忽略新增表；恢复后继续使用原有余额及倍率监控。
