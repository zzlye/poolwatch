# 渠道故障巡检

## 使用方法

在部署服务器运行只读巡检脚本，并将数据库路径替换为实际数据卷路径：

```bash
sudo python3 scripts/diagnose_channels.py /var/lib/docker/volumes/poolwatch_app-data/_data/poolwatch.db
```

脚本只读取已保存的检测结果，报告包含最后检测时间，并不会代替手动刷新或网络复测。退出码 0 表示没有失败渠道，2 表示存在失败或待核查渠道，1 表示读取失败。警告与停用单独统计，不等于所有账号都可调用。脚本不读取凭据列，不解密凭据，不发起登录，不保存原始响应，不修改数据库。

## 常见处理

- chatgpt2api 账号明细过大：该只读接口使用独立的 16 MB 响应上限，其他接口仍使用原来的 1 MB 限制。明细超限或格式损坏时，汇总额度继续更新，并在账号区显示提示和上次成功读取的列表。未知额度显示“读取失败”或“尚未检测”，不作为零额度处理。凭据失效及网络错误仍按原有告警规则处理。

- 站点要求浏览器验证：编辑对应渠道，将密码登录改为网页授权，或者在站点“安全与访问”生成管理访问令牌并填写到监控中。新版站点的用户 ID 可留空，连接测试通过后再保存。
- 当前凭据被拒绝：重新进行网页授权，或更换有效的管理访问令牌。还需检查账号权限，HTTP 401/403 本身不足以证明账号已被封禁。
- 上游服务不可用：检查渠道域名、实际服务进程、容器及反向代理指向的端口。HTTP 502 通常需要修复渠道服务；重启监控应用不代表上游故障已经恢复。
- 渠道连接失败：检查域名解析、地址是否变更和目标网络连通性。
- 警告但检测成功：检查余额阈值和账号状态，不要仅凭警告颜色判定渠道失效。

## 验证原则

公共接口返回 200 只能证明站点响应，不能证明保存的凭据有效。使用现有凭据复测时，只请求对应渠道的只读接口，保留 HTTP 状态码，不记录 Cookie、Token、密码或完整响应。先分别检查监控服务和渠道服务，再决定是否更新适配器。

排查期间不自动清空告警、不关闭渠道，也不通过重启服务掩盖故障。生产环境变更前先按备份文档生成一致性备份。渠道地址与检查结果放在私有运维记录中，不提交到公开仓库。
